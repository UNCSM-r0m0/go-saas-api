Diagrama de Secuencia: Chat con Streaming SSE

Flujo completo desde el mensaje del usuario hasta la respuesta streaming

📋 Explicación del Flujo

1
Usuario envía mensaje — El usuario escribe en el frontend (React/Vercel) y presiona enviar.
2
Frontend hace POST — Envía `POST /api/v1/chat/stream` con el mensaje y modelo seleccionado.
3
API Gateway valida JWT — Extrae el token del header `Authorization`, valida firma y expiración.
4
Rate limiting (Redis) — Consulta `rate_limit:{user_id}` en Redis. Si excedió el límite → 429.
5
Proxy a Chat Service — El gateway reenvía la request al microservicio de chat (puerto 3002).
6
Verificar límite de uso — Usage Service consulta cuántos mensajes envió hoy (sliding window).
7
Guardar mensaje usuario — Persiste el mensaje en PostgreSQL (tabla `messages`).
8
Obtener provider de BD — Lee `ai_providers` + `ai_models` para saber qué endpoint llamar.
9
Enviar a Ollama/OpenAI — HTTP POST con streaming habilitado. Connection pooling reutiliza TCP.
10
Streaming loop (Go routine) — Por cada chunk recibido: parsea → envía al channel → SSE al frontend → render.
11
Guardar respuesta completa — Una vez terminado, persiste la respuesta en PostgreSQL.
12
Incrementar contador — Usage Service actualiza el contador diario en Redis.
13
Cerrar conexión SSE — Envía `[done]` al frontend, cierra el stream gracefully.
