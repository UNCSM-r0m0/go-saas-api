# Artifact Storage Specification

## Purpose
CRUD and serving of artifacts generated by agents (HTML, CSS, JS, Markdown, etc.).

## Requirements

### Requirement: Artifact Creation

The system MUST store artifacts with metadata and content.

#### Scenario: Create artifact

- GIVEN a POST `/artifacts` with `{name, type, content, session_id}`
- WHEN the request is authenticated
- THEN the artifact is persisted to Postgres
- AND the content is stored (inline if <1MB, filesystem if larger)
- AND a `201 Created` with artifact ID is returned

### Requirement: Artifact Retrieval

The system MUST serve artifacts by ID.

#### Scenario: Get artifact

- GIVEN a GET `/artifacts/{id}`
- WHEN the artifact exists and user has access
- THEN the artifact metadata and content URL are returned

#### Scenario: Preview HTML artifact

- GIVEN a GET `/artifacts/{id}/preview`
- WHEN the artifact type is `html`
- THEN the raw HTML content is served with `Content-Type: text/html`
- AND the browser renders the artifact

### Requirement: Artifact Listing

The system MUST list artifacts per user/session.

#### Scenario: List session artifacts

- GIVEN a GET `/artifacts?session_id={id}`
- WHEN the session belongs to the authenticated user
- THEN a paginated list of artifacts is returned

### Requirement: Artifact Versioning

The system MAY support versioning of artifacts.

#### Scenario: Update creates version

- GIVEN a PUT `/artifacts/{id}` with new content
- WHEN the update succeeds
- THEN the version counter increments
- AND previous content is preserved
