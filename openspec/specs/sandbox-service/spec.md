# Sandbox Service Specification

## Purpose
Secure execution environment for code generated by agents. Isolates user-generated code from the host system.

## Requirements

### Requirement: HTML Sandbox

The system MUST serve user-generated HTML in an isolated context.

#### Scenario: Preview HTML artifact

- GIVEN a POST `/sandbox/preview` with HTML content
- WHEN the request is valid
- THEN a sandboxed iframe URL is generated
- AND the HTML is served from an isolated origin/subdomain

### Requirement: Docker Sandbox

The system SHOULD execute untrusted code in Docker containers.

#### Scenario: Execute Python script

- GIVEN a POST `/sandbox/execute` with `{language, code}`
- WHEN the language is supported
- THEN a Docker container is spawned with the code
- AND stdout/stderr are captured
- AND the container is destroyed after execution

#### Scenario: Resource limits

- GIVEN a sandbox execution request
- WHEN the container starts
- THEN it MUST have CPU limit (1 core), memory limit (512MB), and no network
- AND execution timeout is 30 seconds

### Requirement: Security Isolation

The system MUST prevent sandbox escape.

#### Scenario: Blocked system calls

- GIVEN code that attempts `os.system("rm -rf /")`
- WHEN the sandbox executes it
- THEN the syscall is blocked by seccomp
- AND an error is returned without affecting the host

#### Scenario: No root access

- GIVEN any sandbox container
- WHEN it starts
- THEN it runs as non-root user
- AND host filesystem is not mounted
